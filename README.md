# T800 RL 行走策略：仿真部署、鲁棒性评测与蒸馏

在 MuJoCo 中部署众擎 T800 人形机器人的官方预训练 RL 行走策略（MNN 格式），系统评测它的失效边界，再用 PyTorch 把它蒸馏成自己的网络，并尝试提高蒸馏网络的延迟容忍度。自学项目，只在仿真中验证，没有上真机。

## 做了什么

1. **部署**：25 自由度 T800，1083 维观测（15 帧 × 72 维 + 3 维指令），100 Hz 策略推理，500 Hz PD 控制。
2. **评测**：不开窗口批量仿真，覆盖速度跟踪、行走抗推、摩擦与负载、动作延迟与 IMU 噪声。
3. **蒸馏**：行为克隆，再用 DAgger 解决复合误差。
4. **抗延迟**：在含延迟执行的流程中训练学生，设标签前移与不前移的对照组，并测量训练种子的波动。

## 主要发现

| 实验 | 结论 |
|---|---|
| 速度跟踪 | 指令绝对值不超过 0.2 m/s 时原地不动（死区约 ±0.25 m/s）；前进最高约 0.67 m/s；向左走只能达到指令的一半 |
| 行走抗推（推 0.2 s） | 前 450 N、后 500 N、左 300 N、右 150 N |
| 步态相位抗推 | 被推向支撑腿一侧恢复率 0%，被推向摆动腿一侧 77%~88%，左右对称 |
| 摩擦与负载 | 摩擦低于默认值约 0.2 倍失效；负载超过整机质量约 43%（约 36 kg）失效。失效时速度失控比踝关节力矩饱和早约 3 s，排除了电机力矩不足 |
| 延迟与噪声 | 动作延迟上限约 40 ms；噪声会让机器人越走越慢 |
| 行为克隆 | 验证误差很低，但闭环 100% 摔倒（4.5~7 s 后），原因是复合误差 |
| DAgger | vx 0.3~0.6 m/s、无扰动时摔倒率降到 0%，速度跟踪与教师相当；前、后、左三个方向的抗推上限约为教师的 70%，延迟容忍度约 20 ms（教师约 40 ms） |
| 抗延迟学生 | 6 次训练在 30 ms 延迟下均稳定行走（此前为 100% 摔倒）；40 ms 时摔倒率在 20%~90% 间波动，**未超过教师的约 40 ms** |

最后一行里有一个值得注意的发现：训练种子带来的波动，比标签前移与不前移两种方案之间的差异还大，所以单次训练的结果不足以比较方案优劣。

## 复现需要自备的内容

仓库里**没有**以下文件，它们属于众擎，需要自己获得授权后放到对应位置：

- T800 的 MJCF 模型（`t800.xml` 及 `robot/`、`environment/`）
- 官方预训练策略（`MNN-CODE/policy/*.mnn`）

训练数据和蒸馏出的权重也没有上传。依赖：Python 3.11、mujoco、MNN、numpy、matplotlib、PyTorch（CPU 版即可）。

## 局限

- 只在仿真中验证，没有真机实验。
- 评测的种子只控制 ±0.02 rad 的初始扰动，步态很快收敛，多个种子的轨迹几乎相同，不等于多次独立测试。
- 学生只在 vx 0.3~0.6 m/s 的数据上训练和评测。
- 报告中的"可能的原因"均为未验证的推测。
